# Эксперимент: анализ связей группы лиц

Ветка: `experiment/group-face-analysis`

## Что добавлено

- Кнопка **«Анализ связей группы»** в веб-интерфейсе `server_http.py`. Она доступна после обнаружения двух и более лиц.
- Фоновая задача с прогрессом, чтобы поиск нескольких лиц и проверка социальных связей не блокировали HTTP-запрос.
- Поиск кандидатов для каждого лица с порогом сходства.
- Дедупликация кандидатов: несколько изображений одного профиля не считаются разными людьми.
- Для каждого лица сохраняется несколько лучших уникальных профилей-кандидатов; несколько фотографий одного и того же профиля не превращаются в разные личности.
- Ранжирование набора профилей с приоритетом подтверждённых дружеских связей и общих друзей, а не только среднего сходства лиц. Если оба списка друзей успешно получены, но у пары нет ни дружбы, ни общих друзей, пара получает отрицательную оценку.
- Если список друзей недоступен или профиль не имеет числового VK ID, связь считается неизвестной: она не объявляется отсутствующей и не получает отрицательную оценку.
- Если лучший визуальный кандидат не согласуется с профилями остальных лиц по доступным социальным связям, система может оставить это лицо без надёжного совпадения вместо присвоения чужого профиля.
- Два раздельных сигнала пола: классификация лица на исходном фото и в CROP-кандидате по InsightFace Gender & Age, а также указанное поле пола владельца профиля (например, VK `sex=1` — женский, `sex=2` — мужской). Несовпадение с полом профиля получает отдельный, более высокий, но мягкий штраф; он может снизить рейтинг даже если само фото-кандидат визуально классифицирован в тот же класс, что и исходное лицо. Неуказанный пол профиля остаётся нейтральным.
- Граф для выбранной комбинации и список альтернативных комбинаций.
- Постоянные параметры в окне desktop-приложения и временные параметры в браузере.

## Настройки

Постоянные значения открываются в главном окне FaceSearch кнопкой **«Параметры группового анализа»**. Они сохраняются в существующий `settings.xml` и используются сервером при запуске.

Поля, изменённые на странице браузера, применяются только к запущенному анализу и не сохраняются в `settings.xml`.

Параметры:

- минимальное сходство кандидата, %;
- число кандидатов на каждое лицо (1–10);
- вес прямой дружеской связи;
- вес общих друзей;
- вес совпадения города;
- включение/отключение проверки друзей VK;
- включение/отключение проверки пола;
- штраф за несовпадение класса лица по фото (`gender_weight`, 0–10);
- штраф за несовпадение указанного пола профиля (`profile_gender_weight`, 0–30).

## VK и ограничения

Проверка друзей включается по умолчанию, но работает только при наличии рабочего токена, сохранённого загрузчиком VK в `loaders/vk/vk_token.txt`. Оценка пола по фото использует атрибутный модуль Gender & Age из модели InsightFace `buffalo_l`; дополнительная модель и изменение схемы БД не требуются. Предсказания лиц-кандидатов вычисляются по сохранённым CROP и кэшируются в памяти по `face_id`.

Получение, проверка и сохранение токенов остаются в загрузчике VK: «Получить токен через VK ID…» или «Добавить токен v1 вручную…». Анализ подключается к модулю `loaders/vk/vk_downloader.py`, перечитывает его пул токенов при изменении файла и использует штатную ротацию токенов и повторные запросы API. Отдельного ввода или формата токенов в браузере нет. Если рабочие токены отсутствуют, доступ к друзьям закрыт или API возвращает ошибку, анализ продолжится по доступным признакам; интерфейс сообщит о неполных данных. Загружаются только ID друзей, не их профили и фотографии. Для нагрузки введены кеш, ограничение числа кандидатов и ограничение скорости запросов.

## Как интерпретировать результат

В результате визуальное сходство остаётся фильтром кандидатов, но при наличии данных VK основным критерием выбора набора служит согласованность социальных связей. Поэтому кандидат с чуть более низким визуальным сходством может быть выбран вместо визуально более сильного профиля, если первый подтверждён связями с остальными кандидатами, а второй противоречит доступным спискам друзей. Оценка пола по изображению остаётся мягким вспомогательным критерием: несовпадение учитывается только при уверенности не ниже 65% у обеих оценок, а размер ограничен настройкой `gender_weight`. Отдельно учитывается указанное поле пола в карточке профиля с настраиваемым штрафом `profile_gender_weight`; если явного значения нет, штраф не применяется. Даже эти два сигнала не являются жёстким фильтром и сами по себе не подтверждают личность.

Название профиля означает источник, в котором найден сохранённый face crop, и не гарантирует, что владелец профиля — человек на фотографии. Если проверка друзей отключена, не сработала или данные недоступны, результат не является подтверждённым социальным выводом и может ранжироваться преимущественно по сходству лиц. Совпадение города — лишь слабый дополнительный признак.

## Проверка

Базовые модульные тесты находятся в `tests/test_group_analysis.py` и запускаются из корня репозитория:

```powershell
python -m unittest discover -s tests -p "test_group_analysis.py" -v
```

Эта экспериментальная ветка не изменяет `main` и не требует изменения схемы основной базы данных.
