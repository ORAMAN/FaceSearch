Загрузчик аватарок VK для FaceSearch

Установка и запуск
1. Папка загрузчика: FaceSearch\loaders\vk_abatars.
2. При первом запуске выполните setup.bat. Он устанавливает зависимости в общее окружение .venv в корне FaceSearch.
3. Запускайте start_vk_abatars.bat.

Режим работы
- Источник «Каталог вконтакте24.рф» читает публичные карточки пользователей и загружает их аватарки в FaceSearch. Для этого источника токены VK не требуются: API VK не используется. Курсор сохраняется для продолжения обхода; повторяющиеся в активной базе профили пропускаются.
- Укажите стартовый числовой ID пользователя. Загрузчик последовательно увеличивает ID и работает до нажатия «Остановить».
- Настройте число параллельных потоков загрузки.
- Для надёжной обработки загрузчик запрашивает профили через users.get пакетами по 100 ID. При отправке 1000 ID единым запросом в проверке возвращались только 100 объектов, поэтому большие списки разбиваются на небольшие пакеты. Аватарки затем скачиваются параллельно.
- users.search и database.getCities запрашиваются страницами по 100 объектов. Для users.search загрузчик последовательно увеличивает offset и обрабатывает до первых 1000 результатов метода; поле count в ответе — общее количество совпадений, а не число объектов на текущей странице.
- ID, уже представленные в таблице profiles активной базы FaceSearch как https://vk.com/id123 или https://vk.ru/id123, пропускаются до запроса в VK API. Пропуск считается частью последовательного диапазона.
- Сохраняет Avatar.jpg и Avatar.json со штатной структурой метаданных FaceSearch.
- При включённом автоматическом импорте каждая аватарка передаётся в FaceSearch сразу после скачивания и сохранения JSON. Скачивание идёт параллельно, а импорт выполняется из потока-владельца соединения с БД (это безопаснее для SQLite).
- Поддерживаются CROP, создание индекса FAISS после остановки и удаление Avatar.jpg, Avatar.json и пустой папки пользователя после успешного импорта (при неудачном импорте файлы сохраняются для повтора). Каталог пользователя заранее не создаётся, если фото отсутствует или загрузка завершилась ошибкой.
- Следующий ID для продолжения автоматически подставляется в поле после штатной остановки. Перед запуском проверьте это значение.

Токены VK API
- Кнопка «Получить токен через VK ID» открывает в браузере авторизацию для приложения 8101047 с правами друзей, фотографий, статуса и «Доступ в любое время» (offline; scope=66566). Последнее право важно для использования токена при изменении IP-адреса.
- После подтверждения VK перенаправит на blank.html с токеном в URL-фрагменте после #access_token=. Скопируйте полный URL из адресной строки в поле загрузчика и нажмите «Проверить и сохранить». Токен извлекается локально и не попадает в журнал.
- Можно добавить ранее полученный токен v1 вручную. В обоих случаях токен проверяется запросом users.get перед сохранением.
- Токены хранятся в файле vk_token.txt рядом со скриптом. Не публикуйте токен или URL callback.

База FaceSearch
Даже при выключенном автоматическом импорте загрузчик читает profile_url активной БД для пропуска ранее внесённых ID. В этом режиме он не меняет схему таблиц и не импортирует изображения.

Журнал
- [DB-SKIP] — ID уже есть в активной БД; [DB-IMPORTED] — аватар импортирован; [VK-NOT-FOUND] — VK не вернул профиль; [NO-AVATAR] — у профиля нет доступной фотографии; [AVATAR-ERROR] и [DOWNLOAD-ERROR] — ошибка загрузки; [DB-ERROR] — ошибка импорта. Итоговые счётчики показывают количество каждого исхода. Строки журнала окрашиваются по типу результата.


Дополнительный режим «Страница сайта (URL)»
- Выберите источник «Страница сайта (URL)» и вставьте прямую HTTPS-ссылку на HTML-страницу домена вконтакте24.рф.
- Пример: https://вконтакте24.рф/celebrity.html?t=9
- Загружаются карточки профилей с фотографиями, найденные непосредственно на указанной странице. Автоматического перехода на следующие страницы нет: для другой страницы укажите её URL отдельно.
- Режим не использует VK API и не требует токенов. Скачивание, проверка существующих ID, импорт в активный профиль FaceSearch и настройки CROP работают через тот же обработчик, что и существующий режим каталога.
